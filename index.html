How it works

NEGATIVE.LAB is a browser-based film negative → positive converter. You drop a scan of a film negative (camera RAW or JPEG); the app demosaics it, inverts the density, removes the C41 orange mask, and hands you a finished positive image — all locally, in-browser, with no server touching your files.

Pipeline

DecodeRust → WASM
InvertLog-space density
AdjustWebGL2 shader
ExportFull-res PNG
  1. Decode. A Rust crate compiled to WebAssembly parses the RAW file using rawler, then a bilinear Bayer demosaic converts the raw sensor data into linear RGB. JPEGs and PNGs go through the browser's native decoder + sRGB → linear conversion.
  2. Invert. Film response is logarithmic, so we compute density: D = log(base) − log(pixel) per channel. This removes the orange C41 mask and inverts tonality in one step. Naive 1 − pixel or base / pixel in linear space always clips because every image pixel is darker than the rebate.
  3. Adjust. Per-channel auto-levels on density gives us auto white balance for free. Then a WebGL2 fragment shader applies your tone curve, saturation, split-toning, sharpening, crop, and rotation in a single pass. Every slider updates the image live at 60fps because it's all uniforms.
  4. Export. Download renders through the same shader at full crop resolution via a WebGL framebuffer, so what you see is exactly what you get.

Privacy

Your files never leave your device. There is no server processing negatives; the site is 100% static assets served by a CDN. The Rust decoder runs in your browser via WebAssembly and the tone pipeline runs on your GPU. Your session persists in IndexedDB — again, local only.

Supported formats

Camera RAW (decoded by rawler in WASM): DNG, Nikon NEF (non-HE*), Canon CR2/CR3, Sony ARW, Fujifilm RAF, Olympus ORF, Panasonic RW2. Other rawler-supported formats (Pentax PEF, Phase One IIQ, etc.) will attempt to decode too but aren't officially tested.

Standard images (decoded by the browser): JPEG, PNG, WebP.

Not yet supported: Nikon HE / HE* NEFs. libraw hasn't reverse-engineered those compression formats yet. Workaround: run through Adobe's free DNG Converter, then drop the DNG here.

Under the hood

  • Rust — decoder crate compiled once for native (via rsraw + libraw) and again for WASM (via rawler).
  • WebGL2 — the whole tone/crop/rotate pipeline is one fragment shader. Sharpening samples the pipeline at 4 neighbours for a proper unsharp mask on the tone-mapped output.
  • Vite + TypeScript — no framework, no SSR. This is a single-page app that doesn't need any of that.
  • IndexedDB — persists the source file buffers and your per-frame settings; on reload we re-decode and restore.
  • GitHub Actions — rebuilds the WASM automatically on every Rust change; Vercel redeploys the static site.

Presets

Eight curated tone presets — Neutral, Portrait (warm Portra-like), Vivid (Ektar-like), Golden, Cinematic (teal/orange), Faded, Moody, Cool. Each one overrides only the tone and color params, not your crop or rotation. Layer them, then tune.

Why not just Lightroom + NLP?

You can. That workflow costs about $10/month for Lightroom plus ~$100 one-time for Negative Lab Pro. This tool does the same core job — decode, invert, apply a film-like look — for free, without installing anything, and works on Chromebooks and phones too.

The trade-off: no local adjustments, no full curves editor, no XMP round-tripping, no batch presets library. If you're editing a wedding shoot, use Lightroom. If you scanned a few rolls on a weekend and want positives to share, this is faster.
